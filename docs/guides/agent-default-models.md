# Default models for Agents

The Agent model dropdown is the single model entry point for WorkBuddy, WorkBuddy AI, Qoder CN and Claude Desktop. Claude Desktop's visibility controls are available through **Manage visible models** inside that dropdown.

The Agent model selector saves the model for new sessions. Existing conversations retain their own selections. CLI integrations use their supported configuration fields; desktop integrations may need a confirmed restart to reload their configuration. The restart button appears when a running desktop instance predates the applied configuration. A stopped application reads the configuration on launch; a newer instance has no pending restart.

Claude Desktop publishes the chosen visible model first in `inferenceModels` and enables `alwaysStartWithDefaultModel`. The remaining visible models retain their saved order. Hiding the default falls back to the first visible model. Hiding every model leaves no starting model. Disconnect restores the original profile settings. Native observations read the active profile identified by `_meta.json`, rather than a dormant Vary profile.

WorkBuddy, WorkBuddy AI and Qoder CN save new-chat choices in native renderer storage. Their model files alone do not set the desktop composer's selection. Choosing a default in Vary requests device-local control permission the first time. Saving a model leaves a pending restart button on the Agent row; restart confirmation opens only when that button is clicked. An installed Node.js runtime is required. Permission, a model-only plan and readback records are kept under the local `agent-connections/model-control` directory and are excluded from profile exports.

The confirmed launch starts the identity-checked client with a private DevTools pipe. There is no TCP debugging listener or installed-file patch. A detached helper owns the pipe until the client exits, so closing Vary does not close that pipe. It accepts no commands from a network socket. Only the installed application's main renderer is eligible; browser pages, previews and embedded webviews are excluded. A supported Windows installation must match the verified installation paths in the lifecycle adapter; other locations fail without launching a replacement.

On macOS, lifecycle checks read the verified process's kernel creation time. Directly launched Electron clients may omit AppKit launch metadata, which must not block a later confirmed restart. Windows uses the native process creation time for the same identity and freshness checks. Missing or changed process identity still prevents a restart.

The adapter owns only general local new-chat model keys. WorkBuddy uses the native `custom-local:` reference for configured custom model IDs. Its BuddyApp scopes, Qoder remote/runtime-specific scopes, account credentials and conversation settings remain native. Qoder must expose exactly one enabled model with the requested model ID under the managed `varyai` BYOK provider before the choice can be saved. The Qoder primary renderer uses the `qoder-cn-app://renderer/index.html` origin; its other workbench scopes are excluded. The initial composer is reloaded after persistence; subsequent renderer loads seed the same new-chat keys before the application reads them. Later native picker changes remain usable.

A small recovery journal in the client's own storage records model-choice values only. Disconnect restores entries still equal to the bridge's installed value and removes the startup adapter. Later native choices are preserved. If the client is closed, restoration waits for the next confirmed controlled launch. Persisted readback is tied to the exact desired revision; a normal manual client reopen does not turn an already saved default into a pending operation. A changed catalog/default requires another confirmed launch before the new revision can be verified.

TRAE CN (`trae`) and TRAE International (`trae-intl`) are separate Agents. Their official websites are [trae.cn](https://www.trae.cn/) and [trae.ai](https://www.trae.ai/), respectively. Each edition has its own model catalog, selected starting model, connection credential, consent and cleanup outbox. Existing CN identifiers and saved settings remain compatible. Selecting a model targets new sessions in the native modes that support that model; an offline bridge remains pending rather than reporting delivery.

Gateway policies bind to each TRAE edition independently. Requests through its managed provider and protocol-conversion routes retain native authentication while enforcing that edition's model allowlist and token budget and recording its usage.

The editions use `~/.trae-cn/argv.json` and `~/.trae/argv.json`, plus separate native `Trae CN` and `Trae` application-data directories. Consent for one edition does not authorize the other. After granting local connection permission, open the corresponding client and fully restart it once to load its random local debugging endpoint. VaryAI verifies the installed bundle or executable and attaches only to that edition's native chat windows. It neither patches the installed client nor exports account credentials. Disconnect removes only its managed models and restores the launch setting; an offline client retains its cleanup outbox until acknowledgment.

Bridge startup resolves the verified running application copy on macOS and Windows before selecting its Electron runtime. Installing another copy with the same display name does not redirect an already running client's bridge to a different application directory. Ambiguous running copies fail identity checks rather than attaching to an arbitrary window. Shared-model recovery accepts each edition's exact loopback route and still requires matching model identity, endpoint and label. An explicit native model-write rejection is reported separately from waiting for a connection. Native model mutations share one renderer transaction queue. Their IPC deadlines allow up to five minutes for a large catalog, rather than retrying while a previous eight-second call is still writing. Helper startup is serialized per edition; upgrades wait for a compatible resident bridge to finish its model transaction. In Agent mode, the helper awaits the native forced model refresh before recording protected-credential fingerprints; a model-change broadcast alone is not a refresh-completion barrier.

The helper uses a private Unix socket on macOS and an authenticated local named pipe on Windows. Windows bridge and runtime directories receive a protected current-user ACL before helper files or pipe credentials are written. International model routing uses its own local endpoint, separate from CN audit controls. macOS international update metadata comes from the [official download manifest](https://api.trae.ai/icube/api/v1/native/version/trae/latest); CN packages are excluded from international selection. Windows native execution and international client compatibility still require separate acceptance.

Doubao Work retains its official native model selection. Its Vary integration is audit-only and does not substitute shared gateway models for the signed-in official account.

Run `pnpm test:model-default` for synthetic renderer and pipe tests. Rust and renderer component tests cover visibility fallback, active-profile observation, explicit consent, restoration and confirmed restart boundaries. These tests do not grant client control or establish live compatibility with an installed client version; that verification requires explicit user authorization.
