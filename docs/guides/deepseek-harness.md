# DeepSeek Harness Desktop

VaryAI integrates the official DeepSeek Harness desktop application. Install and initialize it separately from the [official download page](https://www.deepseek.com/en/download/), then add **DeepSeek Harness** in **Tools / Agent**. This integration does not install or start the client during detection.

## Shared models and inspection

Use the model dropdown on the DeepSeek Harness row in **Tools / Agent** to connect or change its starting model. VaryAI writes that choice as the default for new Harness sessions. The managed catalog groups models into native OpenAI Chat Completions, OpenAI Responses and Anthropic Messages providers against the local gateway. Routing groups and other targets use the supported shared protocol bridge. Model names, declared image support, context capacity and reasoning choices are projected into Harness's native provider configuration. Harness's fixed reasoning selector exposes upstream `ultra` as `max`, preserving `ultra` as the request value. Unknown selector levels are omitted so one model cannot invalidate the entire provider. Unknown capacity is left to Harness's native defaults, without changing shared upstream metadata.

The desktop profile is `$DSH_HOME/profiles/desktop/cordis.patch.yml`, with `DSH_HOME` defaulting to `~/.dsh`. The Web profile is separate and is not changed. VaryAI adds custom routes to the existing `llm-pi-ai` configuration row, retaining its native providers, and updates the native new-session default model entry. Creating a second pi-ai plugin would duplicate Harness's configurable-provider directory and prevent its routes from loading. Unrelated plugin patches remain unchanged during shared-catalog changes. Configuration ownership is read from native entries, so a client save that removes or relocates comments does not break model reads or reconnection. An empty YAML list becomes a sequence when providers are added. Native default-model switches keep the connection active and survive automatic catalog synchronization, as they do for the other supported agents. Disconnecting restores managed model choices and preserves choices of native providers. Changes to owned endpoints, credentials or model catalogs still require explicit recovery. Invalid patch documents or unsupported YAML expressions stop configuration changes.

Each managed model's native `name` includes its upstream source, for example
`Model A · Team Relay`. The `Vary AI` provider heading identifies the gateway,
not that upstream source. Refreshing an existing connection updates these names
even when Harness continues using an older bare request alias as the model's
`id`. Historical aliases and the selected upstream model remain valid.

VaryAI stores its local gateway credential as `VARYAI_HARNESS_GATEWAY_KEY` in `$DSH_HOME/.credentials.yaml` (native version 1) and points all three managed protocol routes at it through `apiKeyEnv`. This lets Harness resolve authentication and show its native green credential indicator. The green dot confirms that a credential is configured; it does not test connectivity or identify the model used by a conversation. Catalog synchronization upgrades intact older connections that used an Authorization header. A conflicting credential reference, unsupported credential-store version or invalid YAML stops the update without overwriting the native files. On Unix, credential writes use owner-only permissions.

Existing conversations retain their own model selection; switch those inside Harness, or start a new session to use the default chosen in VaryAI. Disconnecting restores the preceding native default, managed provider fields and VaryAI gateway credential. Official account data, other managers' credentials and native credentials added after connecting remain with the client. Native DeepSeek account traffic is outside this adapter's inspection coverage; select a VaryAI model to route that conversation through inspection. Existing pi-ai provider patches with explicit endpoints can use the native API-key routing path. File changes can be reloaded by Harness; if its catalog has not refreshed, quit and reopen it manually.

## Recovering after another manager changes the profile

Use one manager for DeepSeek Harness at a time. If Magpie or another tool also manages Harness, turn off its Harness integration first; the other application can remain running. In VaryAI, click **Reconnect** on the Harness row or turn its connection switch on. Restarting VaryAI alone does not repair a damaged profile.

Harness can remove or rewrite comments when saving its profile. VaryAI recognizes its managed provider entries by YAML structure and route identity, so missing comment markers do not by themselves require repair. Explicit reconnection releases only the provider routes and gateway credential identified by the saved connection record, then rewrites VaryAI's connection fields from the current shared catalog, including changed endpoints, authentication and model lists. It saves private `deepseek-harness-recovery-*.yml` backups of the profile and existing credential store beside the connection record before changing either native file. Effective native provider settings, another manager's disconnect and a native default-model choice are retained. Polling and startup do not rewrite changed owned credentials or endpoints automatically. Invalid YAML, unsupported credential-store versions and ambiguous provider ownership stop recovery without overwriting the native files; restore a known-good backup or contact support in those cases.

## Versions and updates

On macOS, presence and installed versions are read from the official `DeepSeek Harness.app` bundle with identity `com.deepseek.dsh`. The homepage includes this agent in individual and batch update checks. Apple Silicon builds using the installed official Nightly feed can use the existing verified desktop updater. An absent, different or unreadable feed does not offer an automatic update; use Harness's own updater or the official download page. Update checks do not download or replace an application.

## Verification boundaries

Automated coverage uses synthetic profile files, temporary storage and loopback fixtures. It covers reversible projections, foreign edits, readable model labels, reasoning and image declarations, the three native API protocols, shared protocol conversion, update-feed trust and homepage update controls. Reading an installed app's public configuration schema or release feed does not establish live chat, signing or installer acceptance.

The configuration reference is [Magpie's Harness adapter](https://github.com/yetone/magpie/blob/b45d21d5fb39ca0590e653ca33d6f72bb65d117b/internal/agent/dsh.go), especially `dshPutRoute`, `dshKindConfig`, `dshModelLevels` and `dshCreds`. See the [Agent configuration review](../qa/2026-11-10-agent-configuration-parity.md) for remaining adapter differences. VaryAI implements this behavior independently in Rust and manages only its dedicated local gateway credential reference in Harness's native store.
