# Private completed-context authorization: execution specification

> Status: approved design, implementation pending. Approval covers the private backend and loopback tests, not public `redact_restore`, real Codex clients, real models, or release acceptance. Audience: implementers and security reviewers (human + LLM). This document refines [the reversible-tokenization contract](security-dlp-reversible-tokenization-spec.md); it does not replace its limits or claim shipped restoration.

## Outcome and non-goals

Establish a single trustworthy chain: actual outbound attempt → original-protocol completion evidence → validated immutable tokenized snapshot → store-issued completed context. A response ID, call ID, namespace match, cache hit, HTTP success, converter-generated terminal, or successful tool-argument parse cannot substitute for any link.

Keep legacy forwarding, irreversible `redact`, defaults, historical audits, legacy `block` normalization, protective blocking, generic `sk-` restrictions, and the dirty Security Center/event/localization work unchanged. No dependencies, database mapping schema, listener expansion, unsafe code, proxy `unwrap()`/`expect()`, raw configuration/identity diagnostics, or production application launch. Real tool execution is outside this work.

## Private activation and state handoff

Add `security/http_restoration.rs::RestorationGateway` and a private `server.rs::ProxyState.restoration` field. The gateway contains an optional store and captured private selection; clones share the same `DlpTokenStore` inner owner. Production construction in `ProxyServer::new` uses `RestorationGateway::disabled()` (no store/buffers allocated, no selection). Until public action acceptance, no production config, environment variable, request header/body field, command or import may enable it. A `#[cfg(test)]` constructor creates a gateway with one isolated store, explicit synthetic rule IDs and isolated `PayloadBudget`; a test server retains that gateway across requests. Any new shared gateway backing must use the reviewed owners and precharge, not unaccounted Arc allocation.

`security/mod.rs` will add a private admission entry distinct from the legacy `Option<Response>` inspection result: `RestorationAdmission::{Inactive, Rejected(Response), Prepared(DlpHttpRequest)}`. Inactive takes the original legacy path exactly once. Prepared owns captured policy/runtime, strict identity binding, budget, base lease and prepared request; its fields are nonpublic and nonserializable. The handlers move it through an explicit `forward_with_retry` parameter, not a client-controlled header or a forgeable JSON field. The forwarder produces independently owned attempt state, returns the successful actual attempt with `ForwardResult`, and the handlers pass it plus private protocol evidence through every converter/response branch into the final client wrapper. Stream bodies own the guard and lease until completion/drop. Admission must preserve existing fail-closed runtime publication and use `extract_codex_restoration_session_id` before mutation. `server.rs`, `security/http_restoration.rs`, `handler_context.rs`, `forwarder.rs`, `handlers.rs` and `response_processor.rs` are the exact handoff files.

The test-only constructor is also the loopback integration entry. Tests register `security/reversible_integration_tests.rs` in `security/mod.rs`, build the ordinary router with that explicit state, an in-memory database and `127.0.0.1:0`, and configure only a synthetic local upstream. No global test toggle or public selection is introduced. A production default-state regression must prove the private selection cannot be activated by payload/header/config values.

## First executable RED and dependency order

Start with a real existing ownership gap, not a completed-context stub. `DlpRequestLease::authorized_tokens` currently builds a borrowed-reference `Vec` without charging its backing. It is an existing private collector (production preparation uses the allocation-free visitor), and all existing callers only inspect length/emptiness. The first prerequisite is a bounded, precharged borrowed dependency collector usable while the source lease is alive; this is **not** an independent lease or completed authority.

Register `security/reversible_context_tests.rs`. Seed one synthetic mapping through existing `admit` + `prepare_with_budget` using an isolated budget, reserve all remaining store-ledger metadata through existing test accessors, then call existing `authorized_tokens` and assert `CapacityExceeded`. Before the change it successfully allocates/returns, so the test compiles and fails behaviorally. Also assert no source authority/logical-state mutation and that denial releases no foreign reservation. Capture that RED before replacing the collector with `StoreVec<&str>` (or an equally reviewed bounded owner); GREEN proves precharge-before-allocation and subsequent release. Empty collection must allocate nothing. Command: `cargo test --offline --locked --lib --manifest-path src-tauri/Cargo.toml reversible_context_tests`.

Then use this charged collection in a behavior-preserving extraction of authority enumeration, retaining existing visitor and preparation semantics; existing green tests are extraction evidence, not new RED. Do not introduce completed publication until actual-attempt binding and trustworthy completion witnesses are available. Independent attempt fork, publication and resume each require a concrete test path using real implementation dependencies: first add a real producer/consumer via behavior-preserving extraction under green tests, then add the new positive/negative contract tests and record behavioral RED. If no non-placeholder compiled path exists, stop that task and specify the test seam before changing production behavior; do not claim a compile error or always-deny body as RED.

Implementation dependency order is: charged ownership prerequisite → behavior-preserving evidence plumbing and private activation → stricter private completion behaviors (tested through existing converter input/output paths) → actual attempt binding and isolated history → completed publication/resume → common restoration exit and barrier → loopback acceptance. The task table below groups affected files; it does not override this dependency order.

## Authority state machine

1. **Admitted base lease.** Store, namespace, random generation and captured policy revision are fixed. Valid identity grants namespace selection, not historical dependencies. Invalid identity remains request-scoped and cannot resume a completed context.
2. **Attempt candidate.** Fork the approved base dependency set into an independently owned, bounded attempt lease. Only completed, exactly bound history can extend it. A failed attempt cannot contaminate the base or the next provider's lease. Reprepare complete readable context when changing provider; do not transfer a foreign provider cursor.
3. **Bound actual attempt.** The forwarding layer creates a private capability after resolving the actual provider, upstream protocol, target and authentication principal. Bind the exact immutable prepared snapshot and final outbound form. Changing these inputs invalidates the attempt proof. Bind stable auth principal when available; if stable identity cannot be established, conservatively disallow cross-request reuse rather than infer it from an access token or provider display name.
4. **Pending response.** Original protocol parsing accumulates sticky evidence and tokenized snapshots under the same attempt binding. It grants no cursor/call/opaque authority. Drop/cancel/error destroys pending data outside locks.
5. **Validated completion.** Full framing/entity completion, genuine permitted terminal, sticky-error checks, token-version snapshot consistency, allowed normalization provenance, restoration validation and the tool barrier all succeed. A private non-serializable witness represents this state; public IDs, booleans and JSON cannot construct it.
6. **Completed publication.** Stage every index, fingerprint, dependency set and owned tokenized snapshot before locking. Recheck namespace/generation/version and publish all completed ownership atomically, or publish nothing. Only the store issues the reusable capability. Commit immediately before releasing the validated success terminal/tool segment.
7. **Resume.** Resolve exact store/namespace/generation/policy/actual-provider ownership, then transfer only the completed dependency lineage into the new attempt, atomically. Check the exact selected immutable cached item/version and final merged request, including reasoning. Re-run policy arbitration and outbound inspection; inherited authority never bypasses current conflicts.

Local commit and response handoff are a linearization point, not proof of remote receipt, tool execution or task correctness. Cancellation observed before commit publishes nothing. Bytes already handed to a client cannot be retracted. Keep forwarding/protocol outcome, restoration outcome, and external task outcome separate.

## Binding and data ownership

- Capabilities have private fields/constructors and no Debug/Serialize/Deserialize. Do not expose raw shared-pointer/weak handles. Match store identity as well as namespace/generation; identical counters or test keys from another store must fail.
- Provider binding is created inside `forwarder.rs`, not inferred from the handler's initial `ctx.provider`. Represent private descriptors by domain-separated, length-framed memory-only keyed fingerprints, with a secret independent of mapping and audit keys. Never retain/log a raw URL with credentials, auth header, session ID or private provider configuration for diagnostics. Credential rotation is not a reason to broaden a principal binding.
- A completed cursor retains the full approved request dependency lineage, including inherited, omitted-but-pinned, reasoning and opaque dependencies. Maintain output reference occurrences separately. Zero visible output does not erase lineage.
- Call ownership binds the exact tokenized item and reasoning snapshot/version, not merely a call ID. A mutable legacy cache cannot replace that immutable data after authorization. Never make a cache/request hybrid authoritative without checking the final merged item.
- Opaque content is fingerprinted and owned; never decrypted, regex-rewritten or persisted. Unknown, stale, conflicting, cross-provider or ambiguous ownership fails closed.
- Keep the upstream history/cache/usage/tool consumers tokenized. Restored plaintext is exclusively client-bound, memory-owned and lease-scoped. No recursive restoration.

## Completion evidence

Evidence originates before lossy UTF-8 conversion, dropped JSON/events, canonicalization, auto-closing or synthetic completion. Record actual protocol and selected response/choice, terminal reason/status, open blocks, framing/parse/drop/truncation/I/O errors and exact allowed normalizations. Errors are monotonic: later terminals cannot clear them.

| Source               | Required terminal evidence                                                                                                                                                                                         |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Native Responses SSE | Genuine `response.completed` with `response.status=completed`, complete frames/entity, consistent snapshots, no sticky error.                                                                                      |
| Chat SSE             | Selected completion has `finish_reason` of `stop`, `tool_calls` or `function_call`; reject `length`, `content_filter`, ambiguous selection, dropped data and unfinished calls. EOF/`[DONE]` alone is insufficient. |
| Anthropic SSE        | Genuine `message_stop`, allowed `stop_reason` (`end_turn`, `tool_use`, `stop_sequence`), closed blocks and no sticky error. A lone stop reason does not qualify.                                                   |
| Complete JSON        | Equivalent protocol-specific status/reason and fully read valid entity. Preserve JSON provenance rather than pretend synthetic SSE events were received upstream.                                                  |
| Compact JSON         | Successful HTTP, completely read UTF-8 JSON and the conservative envelope below; no invented `response.status`. Retain inherited lineage even without visible token output.                                        |

### Conservative private compact envelope

No existing handler validates a compact completion schema. For the private first implementation, accept a JSON object with unique keys, `object: "response.compaction"`, nonempty valid external `id` (at most 256 bytes), nonnegative integer `created_at`, and nonempty `output` array. Require at least one item of `type: "compaction"`, a valid nonempty `id`, and nonempty string `encrypted_content` within the payload limits. Other supported items are complete recognized `message` output text/refusal and `reasoning` summary/opaque carriers from the main contract, each with valid item IDs; reject tools and unknown item/content types in this initial compact subset. Opaque strings are never restored: fingerprint and bind them to the completed attempt/lineage. Preserve bounded ancillary `usage`, `model` and other noncarrier metadata without using it as completion proof; unknown nested content/output carriers or authorized references outside supported text fail unsupported. Any `error`, failure/incomplete status, malformed/missing required field, duplicate key, trailing JSON, empty output, unsupported structure or incomplete body denies completed publication. This is deliberately tighter than arbitrary provider compact JSON, not a claim of general compact compatibility. An ordinary unleased compact request retains existing passthrough behavior.

Zero visible text/token occurrences may qualify only with a valid nonempty compaction opaque item, fully authorized inbound context, and the unchanged full lineage of its actual attempt. It never means an empty object/array can authorize history. Compact JSON provenance is distinct from SSE; a purported compact stream must meet a separately specified supported protocol or be rejected for leased traffic, not guessed into completion.

### Exact normalization allowlist

For Chat arguments, only changes in insignificant JSON whitespace, equivalent JSON string escaping, and recursive object-key order are allowed, after strict parsing of a present nonempty complete JSON string with unique keys. Preserve decoded keys/strings, array order, booleans/null and exact numeric semantics (including signed zero); no field insertion/removal. The lossy `canonicalize_tool_arguments[_str]` defaults in `proxy/json_canonical.rs` do **not** establish validity: missing, empty/whitespace, invalid, duplicate-key or unexpected structured argument inputs cannot obtain a witness merely because the legacy helper produced `{}`/text. Do not call its `expect()`-using serializer for new restoration work; use the reviewed bounded fallible serialization path. Record the original strict parse outcome before calling an ordinary converter.

For xAI only, the already-supported whole-float-to-integer transform may justify precisely the recorded numeric leaves; reject fractions, out-of-range/nonfinite values or unrelated number changes. Record the exact applied transform; no global numeric tolerance. Existing Read-input sanitization, added fields, automatic block closure, synthetic IDs, missing-argument repair or discarded tool calls cannot establish a restoration completion witness. Add denial cases for every repair path while preserving legacy behavior in unleased traffic.

## Exit and send coverage

- Responses aliases and compact: native JSON/SSE through `response_processor.rs`; Chat, Anthropic and xAI rewrite branches in `handlers.rs`, including SSE-to-JSON fallback and JSON-to-SSE conversion.
- Collect protocol evidence before aggregation/conversion; carry it privately through every branch. Final client wrapper is after history/usage/tool taps and conversion but before the final response body is exposed.
- HTTP/upstream error paths clean up leases but never restore error payloads or issue completed authority. Unsupported carriers/routes fail before forwarding for participating restoration traffic.
- Before every actual send, validate history ownership, generation, policy conflicts and protected plaintext after all enrichment/conversion/overrides/filtering. Use one bounded encoded candidate; never fall back to the original plaintext or convert core DLP failures into provider retries.
- Preserve guard lifetimes, cancellation, timeouts and response status. Prefer identity encoding for leased SSE; reject compressed SSE without a designed bounded decoder. Rebuild length/encoding/transfer headers and invalidate ETag/Digest/Content-MD5 when bytes change.
- On the first locally executable tool, hold that item and all later events, including token-free tools and success terminal. Only a validated complete response releases the segment. Failure discards it and emits a fixed failure/close, never success `[DONE]`.

## Budgets and lifetime invariants

Retain the authoritative initial limits: 256 namespaces; 4096 mappings/dependencies and 4 MiB plaintext per namespace; 65536 global mappings/64 MiB plaintext; 16 MiB metadata; 30-minute idle TTL with active leases pinned; 1 MiB fragment/event/argument; 1024 cursor/opaque ownership entries per namespace and 16384 globally; 256-byte external IDs; 8 MiB/128-tool barrier; separate shared 64 MiB restoration payload budget and existing 128 MiB nonstream ceiling. Explicitly bound call-index slots within charged ownership records; no unbounded auxiliary index.

Use `StoreVec`, `SharedAllocation`, persistent ledger and the existing payload owners, not guessed HashMap/regex allocation formulas. Precharge actual backing/copies and full retained-old/new growth peaks. Hashing, plaintext comparison, validation, scanning, copying, serialization, I/O, waits, allocation and sensitive destruction stay outside token-store locks; no forwarding database locks. Use versioned optimistic publication with bounded retries. Expiry detaches records/index backing and destroys them outside locks before releasing logical charges/pins, including unwind. Anonymous requests cannot mint resumable completed contexts.

Regex compilation/search/captures/cache allocation ownership remains unproved. PII traversal and keyword precompilation do not close it. Do not retry or bypass denied dependency/std source access. Keep public enablement blocked; requested backing accounting is not process RSS, allocator bookkeeping, OOM recovery or zeroization proof.
