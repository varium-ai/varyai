## Decision and scope

Keep existing irreversible `redact` placeholders (`[REDACTED]` and `[REDACTED_PRIVATE_KEY]`). The historical proposal describes an explicitly selected per-rule action, `redact_restore`, that replaces eligible outbound sensitive text with a locally mapped reference, then restores only authorized references in supported responses before returning to a local Codex client. Under the approved format migration, only newly generated references use `rredact-{type}-{token}-ai`; legacy syntax remains recognition-only as specified below. Restoration cannot make a model understand unseen plaintext or guarantee correct tool/code semantics. No upstream lookup or plaintext recovery interface is proposed.

First phase: Codex HTTP Responses and `/responses/compact`, including the supported `/responses`, `/v1/responses`, `/v1/v1/responses`, and `/codex/v1/responses` aliases, native Responses, Chat/Anthropic-to-Responses conversion, and xAI namespace recovery; JSON and SSE. Other clients, direct Chat, WebSocket, and remote shared mappings are **not supported**. A valid new-action match on an already-DLP-enabled unsupported route must reject before forwarding, not send plaintext or silently degrade to `redact`. No new coverage for uninspected traffic is implied. Do not broaden the local proxy's loopback-only listener.

### Capability levels and model limitations

| Situation                                                                                    | Proposed guarantee / limitation                                                                                                                                                                        |
| -------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Complete opaque value passed as a string to a dedicated local tool                           | Restore the exact value only when the model copies the correct full token and the schema accepts it; separately verify the actual task result.                                                         |
| Shell, SQL, patch, source code, regex, URL fragments or JSON embedded in a text value        | Exact insertion only. Outer JSON validity does not establish inner quoting, line count, syntax or semantics. Do not auto-execute model output.                                                         |
| Format analysis, slicing, encoding, hashing, derived digits, or numeric/fixed-format schemas | Unsupported: the model sees a token, not the original value; restoration cannot repair computations or incompatible schemas.                                                                           |
| Upstream hosted tools or local tools with network access                                     | Restoration is local on the return path; it cannot supply upstream tools with plaintext or prevent later exfiltration by a separately authorized local tool. Preserve harness approval and sandboxing. |

This does not restore old irreversible placeholders, maps lost on restart, undetected fields, non-text/opaque content, or content intentionally allowed/audited. A normal string token is not a model-native special token. A missing token or another valid but wrong token can yield a protocol-complete response with an incorrect task result; token corruption without a recognizable prefix may be undetectable. Never market this as end-to-end zero leakage or seamless coding support. Controlled environment-variable or dedicated secret-reference tools may be safer for coding, but are not implemented or authorized by this proposal.

## Historical baseline and compatibility

The existing engine in `src-tauri/src/proxy/security/engine.rs` redacts and reinspects request copies; `src-tauri/src/proxy/security/mod.rs` dispatches inspection and asynchronous audits; `src-tauri/src/proxy/handlers.rs` has multiple Codex response/compact exits; `src-tauri/src/proxy/session.rs` extracts client session identities, while `previous_response_id` is not a stable identity. `src-tauri/src/proxy/providers/codex_chat_history.rs` and `src-tauri/src/proxy/forwarder.rs` can supply history after initial inspection. These are integration constraints, **not evidence that restoration exists**. Existing security events are request/observation records, not restoration outcomes.

Add a precisely serialized Rust `AuditAction::RedactRestore` (`#[serde(rename = "redact_restore")]`, since lowercase renaming alone would serialize `redactrestore`) and TypeScript `AuditAction` member. Preserve all existing defaults, saved actions, legacy `block` normalization, historical audits, restricted generic `sk-` notice (`audit`/`allow` only), and the runtime protective block. Explicitly support round-trip through built-in overrides, custom rule parsing, commands, DAO, import, UI controls, notifications and four runtime languages (`en`, `zh`, `ja`, `zh-TW`); reject misspellings, never default them to `allow`. Existing TEXT storage needs no mapping/key schema migration. Both Security Center and legacy settings controls must convey scope and tool risks; do not introduce a selectable new `block` action. An imported doc does not change those controls.

Only enable restoration processing when DLP is enabled and the captured runtime includes an enabled rule allowed to use `redact_restore`, or when a recognized prior restoration dependency must be validated. No token mapping or response buffer for ordinary legacy `redact` traffic. A valid restoration dependency must match the captured policy generation and request lease, even when no new secret matches. During restoration policy mode reject unknown/expired/ambiguous cursors or opaque history; without it do not impose new cursor restrictions on ordinary traffic. Recognizable old tokens must not pass as authorized references just because the DLP switch is off. A request without a validated stable session identity can restore its own request-scoped references but cannot claim multi-turn continuity.

### Policy generation and audit semantics

Capture the runtime and a separate private `restoration_policy_revision` atomically at admission. Changes to DLP enablement, rule enablement, action, expression or detection catalog close the old generation to **new** leases; name/description or audit presentation changes do not. Already admitted requests can finish using their snapshot; late cursors remain old-generation. When a restoration-related configuration change is being saved/published, pause new affected HTTP DLP admissions before persistence. Save and publish must both succeed before reporting success; if persistence may have committed but runtime publication fails, retain fail-closed admission (`dlp_unavailable`) until a successful reload/republication. Do not hold database locks in forwarding or fall back to stale authorization. Rollback to an older binary requires changing new actions to supported values first and rebuilding readable context, never rewriting historical audits.

`action_taken=redact_restore` would record a successfully prepared outbound **request action**, not completed restoration or tool execution. Conflicting/mixed irreversible findings record `redact`; action aggregation must not combine the two groups. Record the effective request action only at the first permitted outbound attempt after history augmentation/conversion/reinspection; a pre-forward protective refusal records `block` for actual non-allow findings. Avoid duplicate findings on retry; new history findings are recorded on their own permitted attempt. Ordinary audit/usage/observation queue failures remain nonblocking, while core authorization and restoration errors fail closed. Proposed `DlpRestoreOutcome = NotRequired | InProgress | Completed { restored_occurrences } | Failed { code } | Cancelled` is private to the response wrapper and tests, **not** persisted or exposed as a success statistic. `Completed` with zero occurrences is possible and is not task success.

## Token and authorization contract

New-generation grammar: `rredact-{type}-{token}-ai`. Hyphens delimit the fields; underscores **inside** a type name are literal and must not become hyphens. `{token}` is the first 10 bytes of HMAC-SHA-256 encoded as exactly 20 lowercase hex characters (`[0-9a-f]{20}`). A new reference is `32 + type.len()` ASCII bytes, ranging from 37 to 43 bytes; it is no longer fixed at 31 bytes. The maximum viable incomplete SSE reference tail is 42 bytes (43 minus one).

| Category         | Exact type    | Meaning                                                           |
| ---------------- | ------------- | ----------------------------------------------------------------- |
| `Phone`          | `cn_phone`    | Chinese phone number                                              |
| `IdCard`         | `cn_id_card`  | Chinese identity card                                             |
| `PrivateKey`     | `private_key` | Private key                                                       |
| `ApiKey`         | `api_token`   | API token/key                                                     |
| `Database`       | `db_conn`     | Credentialed database connection                                  |
| `Password`       | `password`    | Password                                                          |
| `Infrastructure` | `infra`       | Infrastructure data, including addresses; not an IP-only category |
| `Personal`       | `personal`    | Other personal information                                        |
| `Custom`         | `custom`      | Custom secret                                                     |
| `Mixed`          | `mixed`       | Mixed category                                                    |

These names label existing categories; the format migration does not expand detector or carrier scope. Grammar recognition is **never authorization**. The namespace key and internal HMAC domain remain unchanged; do not rotate the key or rename the domain merely because the external spelling changes.

```text
K_namespace = existing_namespace_key       # private, memory-only 32-byte key for this namespace generation
raw = UTF8(exact decoded logical plaintext) # do not trim, case-fold or Unicode-normalize
message = b"vary-dlp-token-v1\0" || U64_BE(len(raw)) || raw
digest = lower_hex(HMAC_SHA256(K_namespace, message)[0:10])
reference = "rredact-" || stored_type || "-" || digest || "-ai"
```

Use synthetic tests to verify deterministic HMAC construction and encoding without publishing key/plaintext pairs, digest values or complete reference vectors. Category is not part of the HMAC; exact plaintext deduplicates to one reference per namespace/generation. At first creation select a category deterministically: if one category covers the whole merged span, prefer `PrivateKey > Database > ApiKey > Password > IdCard > Phone > Infrastructure > Personal > Custom`; otherwise use `Mixed`. Same-plaintext concurrent inserts commit atomically and reuse the winner's category. Different plaintext with the same truncated digest, or collision with a literal reference in input, aborts the transaction with a fixed error; do not overwrite, regenerate a key, or append randomness. HMAC is not encryption: recovery is a lease-scoped lookup only, with no upstream query API. It exposes category and within-session equality; repeated attacker-controlled inputs can still enable online comparison.

Legacy recognition-only grammar remains `vary_<cc>_<token>_ai`, with a two-character category code from `ph`, `id`, `pk`, `ak`, `db`, `pw`, `ip`, `pi`, `cu`, or `mx`, and the same 20-lowercase-hex token grammar. Complete legacy references are recognized but rejected as context unavailable, not rewritten, restored or authorized as aliases of new references. They are not newly generated. In strict request/history and response carriers, damaged or unfinished candidates after a known new or legacy category header still reject. Unknown type/code nonmatches grant no authority and must not hide nested or later complete references.

The historical design assigns `DlpTokenStore` to proxy state, with per-app, validated-client-session/request namespace and random generation, separate HMAC key, indices, budgets and opaque/cursor ownership. `DlpRequestLease` pins only mappings actually issued or proven as history dependencies in this request snapshot. `DlpPreparedRequest` owns the inspected candidate and non-sensitive audit summary. None of these objects, their keys or plaintext should be serialized, formatted in Debug, logged, audited or persisted. Do not reuse the audit fingerprint secret. A complete current-format reference must match the **full stored mapping**, including exact type and spelling, and the original request lease's namespace, generation and attempt authority; a matching digest alone is insufficient. Restore at most once, never recursively; unknown complete references, cross-session references or unauthorized cached call IDs fail.

Ordinary `message.content[].output_text.text` and its corresponding Responses SSE text events use exact recognition: preserve nonmatches exactly, including malformed or unfinished literals and unknown types, while continuing to scan nested and later starts for complete references. A complete legacy or unauthorized current-format reference still fails. This nonmatch rule does not extend to request admission/history, tool arguments or inputs, reasoning, refusal, metadata or keys; their strict authorization and carrier boundaries remain unchanged. Detect across UTF-8/chunk boundaries without guessing, fuzzy repair, alias authorization or syntax rewriting.

### Atomic outbound transaction and carrier rules

1. Capture identity, runtime/revision and cursor before rewriting; extract supported text, preserve detector semantics and original UTF-8 spans. Parse function arguments as nested JSON where mutation is needed: mutate string leaves, not keys/numbers or serialized JSON bytes. Track existing authorized token references explicitly.
2. Decide **effective** actions before allocating tokens: any effective `block` denies the request; overlapping redaction components choose `redact > redact_restore`, and a whole irreversible component stays irreversible (preserve private-key placeholder precedence). Across fields, if an irreversible exact raw string and a candidate are equal or contain one another, iteratively mark the candidate irreversible too. A leased historical mapping conflicting with this irreversible set instead returns `dlp_policy_conflict`; never expand it and then forward.
3. For remaining `redact_restore` spans, allocate/reuse bounded mappings with collision detection; for `redact`, keep existing placeholders. Reinspect the candidate; exempt **only** token spans proven to belong to the current lease, and reject residual protected plaintext. Commit atomically or roll back new entries. No candidate is sent upstream on failure.
4. Before **each** actual attempt, including retries/fallback, Chat history augmentation and protocol conversion, validate ownership, generation, action conflicts and outbound plaintext. Reuse the prepared snapshot, never retry with original plaintext. New history mappings join the same lease atomically only after reinspection; a now-incompatible dependency rejects that attempt.

A restoration-processing request may edit only the recognized readable `instructions`, `input`/`prompt` text, readable `input[].content`, decoded string leaves of `function_call.arguments`, readable `function_call_output.output`/`custom_tool_call_output.output`, `custom_tool_call.input`, and known visible reasoning history. A sensitive match in an existing inspected-but-nonwritable item ID, `call_id`, tool name/namespace or unknown value must be rejected rather than silently skipped or mutated; object keys are not newly scanned. `previous_response_id` and session headers are identity/cursor inputs, not free text. Do not regex-rewrite `encrypted_content`, signatures or compact opaque blobs; only validate their provenance. Do not expand inspection to model parameters, tool schemas, nontext media or previously uninspected fields. Ordinary paths with no restoration participation retain their old detector/writer behavior.

## Session, cursor and bounded memory

Use `session.rs::extract_client_session_id` precedence; accept only nonempty stable IDs up to 256 bytes without whitespace/control characters. `previous_response_id` indexes `(app, generation, actual provider, response ID)` and authorized dependency sets, **not** a secret bearer credential. A known cursor belongs to one session and a completed response; missing/old/cross-provider or ambiguous cursors require full readable context, not guesses. History and Chat bridge cache remain upstream-tokenized; check namespace ownership even for a globally unique cached `call_id`. Full context can establish a new generation; process restart loses all keys/maps. For compact, store only opaque fingerprints and dependency ownership in memory; reject unknown or stale opaque history when restoration is active; do not decrypt or persist compact data. Successful complete output alone registers reusable cursors, not partial SSE events.

These are **proposed initial limits**, not measured performance: idle namespace TTL 30 minutes (active leases pin it); 4096 entries and 4 MiB plaintext per namespace; 1 MiB per fragment; globally 256 namespaces, 65536 entries, 64 MiB plaintext, plus 16 MiB conservatively accounted metadata. Limit cursors/opaque fingerprints to 1024 per namespace and 16384 globally, external IDs to 256 bytes and each dependency set to 4096 entries. Limit each SSE event and each tool argument buffer to 1 MiB, a response tool-barrier queue to 8 MiB/128 tools, and _separate_ global restoration payload buffers to 64 MiB. Nonstreaming response remains at or below existing `MAX_RESPONSE_BODY_BYTES` (currently 128 MiB) **and** the global restoration budget. Reserve bytes at first growth: framed SSE before history/converters, decompression and body chunks before accumulation, JSON/snapshot/serialization copies before building, and cached copies while retained. Count allocations conservatively; sharing immutable bytes counts once, distinct copies separately. Fail before unbounded buffering, release reservations on cancellation/failure, evict only unleased namespaces, and do not hold locks across scanning, I/O, network waits or blocking transactions. These limits do not cap process RSS or guarantee physical zeroization on drop.

## Response exit and completion contract

All nonempty effective leases must reach a single **post-conversion** Codex Responses client wrapper, including compact and conversion branches that return without `process_response`. Preserve cancellation, guard, timeouts, entity-header correctness and bounded decompression. Ordinary upstream caches, usage accounting and tool observation see **tokenized** output, never restored plaintext; this can reduce risk-observation semantics and must not be marketed as equivalent detection. Never restore an upstream error, response header, usage, model, tool definition, signature or unknown opaque field.

Only restore recognized Responses fields: `message.content[].output_text.text` and visible refusal text; visible `reasoning.summary[].summary_text.text` and supported deltas/done; known bridge-tool `reasoning_content` copies; string leaves inside decoded `function_call.arguments` JSON (re-encode valid JSON without changing keys or number types); `custom_tool_call.input` as free text; and corresponding added/done/completed snapshots. Unknown response carrier containing an authorized token fails as unsupported, not apparently complete. Rebuild body/entity headers (`Content-Length`, `Content-Encoding`, `Transfer-Encoding`, applicable ETag/Digest/Content-MD5). Prefer `Accept-Encoding: identity` for leased SSE; compressed SSE without a designed streaming decoder fails rather than byte-replacing it. Nonstreaming decoding remains bounded.

Parse HTTP bytes, UTF-8, complete LF/CRLF SSE frames (multiline `data`, comments, heartbeats, `[DONE]`), and event JSON in order; one network chunk is not one event. Carry **private** `CompletionEvidence` through converters: actual protocol, explicit terminal status/reason, parse/drop/truncation errors, and applied supported normalizations. Native Responses requires `response.completed` and `status=completed`; Chat requires selected completion `finish_reason` of `stop`, `tool_calls` or `function_call`; Anthropic requires valid `message_stop` and allowed `stop_reason` of `end_turn`, `tool_use` or `stop_sequence`. EOF/`[DONE]` alone, `length`, `content_filter`, `max_tokens`, incomplete, dropped/invalid data, and open blocks are not completion. JSON aggregation must supply equivalent evidence; compact JSON may use its valid complete output envelope, successful HTTP and full body instead of inventing response.status. Error evidence cannot be cleared by a later completed event.

Track response/item/content/field independently. In ordinary output-text delta forwarding retain at most 42 bytes of viable incomplete reference tail (maximum 43-byte new reference length minus one), respecting UTF-8 boundaries. At a validated field boundary, release a remaining nonmatch unchanged, including an unfinished known-header literal; continue scanning nested and later complete references. Strict carriers still reject malformed or unfinished candidates after a known new or legacy category header. Compare unmodified token-version concatenated deltas and all final snapshots before restoring; for function arguments compare parsed JSON semantics while rejecting duplicate keys and preserving array order. Reuse **only** the existing xAI whole-float-to-integer and Chat canonicalization when completion evidence attests they ran; do not invent numeric tolerance or repair missing JSON. Generate one restored final value, then ensure replayed delta concatenation is byte-identical to done/item/completed copies. Do not change event count/order/type/IDs/sequence_number or invent usage events; where necessary put the complete restored argument in the first existing argument delta and empty the remaining existing argument deltas.

**Tool commit barrier:** with a nonempty restoration lease, on the first locally executable tool item buffer that item and _all later events_, including token-free tools and success terminal, until complete response evidence and all consistency checks pass. Ordinary text before the barrier may stream. On success replay the original event positions with validated restored fields and terminal last; on any failure, timeout, cancellation, budget overrun or unknown mapping discard the entire tool segment. This is a correctness-over-latency choice and assumes a tested Codex harness; it does not prove arbitrary third-party clients never execute partial calls. Do not grant tool execution authority merely because restoration succeeded.

## Fixed errors and safe degradation

Never include plaintext, tokens, session IDs, upstream raw payload, parser excerpts or private config in client errors/logs. Before forwarding use fixed-code native error envelopes: `dlp_context_unavailable` (400, stale/missing dependency), `dlp_policy_conflict` (400), `dlp_restore_unsupported` (400 on unsupported entry), `dlp_redaction_failed` (400), `dlp_unavailable`/`dlp_capacity_exceeded`/`dlp_token_collision` (503). On response failure use `dlp_restore_failed` or `dlp_restore_unsupported` (502). Compatible Codex errors use `error.{message,type,code,param}` with fixed message, type `invalid_request_error` or `server_error`, and null param. Other clients retain their native error shape. After SSE headers are sent, emit a fixed `response.failed` / `status=failed` and close (or simply close if writing fails); never emit success `[DONE]` or release buffered tools. Core mapping/lease/redaction/response failures do **not** become provider retries with plaintext fallback. Incidental audit, usage, latency and observation failures remain nonblocking.
