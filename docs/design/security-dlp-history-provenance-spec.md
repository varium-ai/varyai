# DLP history provenance — approved execution specification

> **Status: approved target design, not implementation or test acceptance.** Audience: human implementers, security reviewers, and LLM coding agents. Source inspection and document reviews are dated 2026-10-31 against an actively changing working tree. This task creates this document only; it does not authorize edits to other files, claim that the target is implemented, or establish client, model, installer, or release compatibility.

## 1. Decision in brief

Keep DLP on incoming user content and tool results. Preserve upstream reasoning **text leaf values** without scanning, redacting, or restoring their contents, even when a value contains a complete token-looking reference. That exception is directional: incoming reasoning is untrusted unless a private, in-memory record proves that this proxy previously delivered the exact complete text in the same supported protocol leaf shape, under the same live namespace and actual attempt binding. An assistant role, reasoning field name, response ID, cache entry, or matching digest alone is not proof.

Proven ordinary assistant `output_text` history receives a narrower exception: malformed/nonmatching token examples can remain text, but every complete reference, including nested or later references, still needs strict request-local authorization. Never confuse that behavior with the full reasoning-text exception. Protocol structure, keys, nonexempt values, resource limits, original completion evidence, immutable raw snapshots, and executable tool barriers stay strict in both cases.

Provenance is optional and memory-only. Its charged capture is capped at 256 KiB per response, 1 MiB per namespace, and 8 MiB globally. A capture miss discards the entire proposed response proof without interrupting otherwise valid forwarding. Generic Chat must not synthesize `"tool call"`; only an explicit default-off compatibility capability may request a placeholder. Long `<thinking>...</thinking>` parsing requires exact `outputFormat = thinking_tags`, never a global text filter. Existing short `<think>...</think>` behavior remains unchanged.

## 2. Scope, terms, and preserved contracts

### Goals

1. Stop reinterpreting supported upstream reasoning text as client input or a restoration carrier.
2. Permit exact replay of previously delivered reasoning without creating a client-controlled bypass.
3. Preserve ordinary assistant token-format examples without laundering complete references.
4. Make every admission, audit, planning, conversion, and final-send check agree about the same eligible leaf.
5. Keep proof storage bounded, optional, nonpersistent, and independent of mandatory completion validation.

### Non-goals and forbidden scope expansion

No database/schema migration, new dependency, public provenance header/JSON field, client-issued capability, broad scanner relaxation, generic reasoning-object exemption, automatic cache/legacy recovery, or new production activation switch. Do not replace missing reasoning with a fabricated history proof. Do not change tool argument normalization, token grammar/category authorization, security-policy defaults, media semantics, tool execution permissions, or response completion semantics. No application launch, installation, live upstream/model/network check, production credential access, or commit is part of this task.

Preserve [AGENTS.md](../../AGENTS.md), [the current security architecture](../architecture/security-audit.md), and unrelated dirty work. The [reversible-tokenization proposal](security-dlp-reversible-tokenization-spec.md) remains a historical proposal with its own limited reference-format approval; this document does not rewrite its unaccepted sections or disclaimers. The [completed-context execution specification](security-dlp-completed-context-execution-spec.md), [response-wire execution specification](security-dlp-response-wire-execution-spec.md), and [text-fallback execution specification](security-dlp-text-fallback-execution-spec.md) retain their historical approval/verification limits. In particular, this design does not activate whole-field projection or claim production acceptance for it.

| Strict fallback      | Existing detection/redaction/blocking and reference rules, not automatic acceptance or automatic rejection of all history.                                                                                                                                                                                        |

A reasoning exception never skips its enclosing item. For example, a proven `reasoning_content` value next to a tool `arguments` string leaves the arguments, call ID, name, type, namespace, and status strict. A malformed outer token example in ordinary output must not hide a complete nested reference or a later valid reference.

## 4. Proof contract and lifetime

### Exact identity

A record MUST own immutable complete decoded string bytes and the typed source-derived leaf shape, and compare both exactly. Do not add content hashing as a proof mechanism, lookup fallback, diagnostic, or persistence format. Existing internal binding/call digests remain separate and never substitute for owned delivered text.

The leaf descriptor includes client-facing protocol family, assistant ownership, item/block/part kind, relative structural field path, relevant validated item/call identity when present, and the leaf's role within that item. Validate enclosing types, allowed keys, string/nonstring shape, and identity relationships independently. Absolute top-level `input[]` offsets are not identity: history may be prepended or appended. Internal part order/shape and semantic ownership must still agree. Whitespace, UTF-8 normalization, trimming, concatenation, splitting, reparenting, and changed protocol shapes are not exact equality. If mapping is ambiguous, take strict fallback. There is no fuzzy, suffix, substring, ID-only, or model-name heuristic.

Bind the record to all of:

- Store instance, namespace/session identity, live namespace lifetime, generation, and captured policy revision.
- Actual selected provider, upstream protocol, final target URL/route including security-relevant query/operation, and actual auth principal/account after overrides and refresh.
- Client-facing protocol/leaf descriptor. A converter may carry a private, explicit source-to-target leaf correspondence only when it proves an unchanged value and a supported transformation. Otherwise strict fallback applies after conversion.

A missing stable session or reusable actual principal cannot issue reusable proof. Provider name, configured base URL, handler's initial provider, or an anticipated auth value cannot stand in for actual binding. Failover, endpoint/protocol/account change, namespace expiry/eviction/reset, policy change, generation change, store replacement, and restart invalidate eligibility. Existing `OperationLineage` Responses/compact transfer permission MUST NOT implicitly authorize delivered-leaf proof; this feature requires the exact actual binding.

### State machine and API responsibilities

The following names are **proposed internal contracts**, not claims that these APIs exist:

```text
NoProof
  -> PendingDeliveredCapture (optional reservations; no authority)
  -> ValidatedDelivery (mandatory completion, snapshots, encoding, emission)
  -> PublishedResponseProof (atomic, all eligible leaves or none)
  -> DeferredHistoryCandidate (borrowed exact lookup; no send authority)
  -> BoundLeafCapability (actual binding verified; exact text/shape rechecked)
  -> FinalOutboundRecheck -> Send

Any optional capture failure -> NoProof
Any proof invalidation/mismatch -> strict fallback, or existing strict refusal
Any mandatory validation failure -> existing failure; publish no proof
```

| Proposed contract                       | Input/output and error rule                                                                                                                                                                                                                                  |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `PendingDeliveredCapture::observe_leaf` | Observe final delivered logical text with a typed descriptor; reserve before copy. Any response-local miss disables the entire capture and releases its owned staging data.                                                                                  |
| `publish_delivered_response`            | Accept a verified mandatory completion/delivery boundary, actual binding, and fully staged optional record. Recheck namespace/policy/generation while atomically publishing. No partial leaf set. Optional failure returns no proof, not a forwarding error. |
| `classify_history_candidates`           | Borrow the immutable original request; validate envelope/keys/nonexempt values and match exact text/shape under live namespace/policy/generation. Return private non-sendable candidates, not a public flag.                                                 |
| `bind_history_candidates`               | Verify actual provider/protocol/target/auth, liveness, text, and shape before issuing leaf capabilities; mismatch must redo strict inspection/preparation or refuse under existing rules before sending anything.                                            |
| `recheck_outbound_leaves`               | After enrichment, conversion, model/body/header overrides, and final serialization preparation, verify the exact transformed leaf mapping and final actual binding. Unknown/new/changed leaves are strict.                                                   |

All capability-bearing types are private, nonserializable, and have no payload-bearing `Debug` implementation. Request JSON, headers, restored cache values, and tests outside the privileged fixture constructor cannot mint them. Share an immutable charged owner, not a boolean copied onto an unrelated body. Lifetime pins prevent eviction/replacement from leaving stale authority; liveness/generation checks still run at each security boundary. No database persistence or startup/legacy cache reconstruction is allowed.

## 5. Mandatory data flow and boundaries

### Response path

1. Capture original upstream protocol and transport evidence before conversion or normalization. Maintain current raw/decompressed/frame/workspace limits and owner lifetimes.
2. Validate envelope keys, allowed shapes, identities, nonexempt text, executable items, and original completion evidence. Only typed reasoning text values bypass content/reference processing. Reasoning text remains available to mandatory raw delta/done/part/item/final snapshot comparison.
3. Preserve supported reasoning leaf bytes in JSON and SSE. Do not run them through `restore_text_with_lease`, token tail buffering/grammar diagnostics, the detector, or token dependency collection. Keep structural tracking and mandatory raw snapshots independent; do not delete them when optional capture fails.
4. Restore ordinary output/tool carriers using their existing authorization rules. Retain raw tokenized source snapshots and completed-call/dependency lineage. Reasoning literals must not be added to token authority or rejected by the completed-context publication/resume scan merely for looking like a token. Adjust only the typed reasoning-leaf processing, not mandatory call snapshot equality or tool payload validation.
5. At the final client wrapper, capture the actual logical delivered text and descriptor, independently of raw snapshots and legacy history caches. This includes reasoning-only and text-only responses with **zero active token mappings**; an `is_empty()`/`has_active_tokens()` early return must not silently make them unprovable when the feature's admitted request context is available. Do not activate new public restoration behavior to achieve this.
6. For JSON, finish mandatory validation and final encoding before optional publication at the release boundary. For SSE, capture the concatenated delivered logical value across arbitrary UTF-8/frame/token splits, not one proof per delta, and publish only after original clean entity completion, all mandatory snapshot/tool checks, terminal encoding, and successful terminal release. Earlier streamed text never authorizes partial proof. On cancellation, malformed trailing data, incomplete UTF-8/frame, EOF failure, or encoding failure, drop the pending proof.
7. Optional publication is all-or-none for the eligible reasoning and ordinary output leaves of that response. It does not replace or weaken mandatory completed-context publication. It must never publish first and discover a mandatory failure afterward. Existing text-forwarding timing can remain unchanged; do not introduce whole-response buffering solely for proof.

### Request path

1. Capture immutable original input plus the existing atomic policy/runtime admission snapshot. Locate possible proof matches using borrowed bounded traversal **before** strict scanning can reject a candidate's exempt token-looking bytes. Envelope keys and all nonexempt leaves remain strict at admission.
2. Before actual binding is known, keep a possible exact leaf match deferred. It may defer only its leaf-specific inspection decision. Do not treat it as independently readable history, skip the entire admission pass, mutate it into authority, or permit any transport call.
3. For each actual provider attempt, bind candidates and recheck all required lifetime/identity fields. Only then apply the behavior matrix. On missing/changed proof, run strict fallback on the original value before preparation; if safe strict fallback cannot be completed, refuse. Do not send a speculative body and validate later.
4. Carry the same verified per-leaf classification through reference discovery, request-history extraction, initial/attempt/refusal audits, `CodexRequestCarriers`, detector spans, logical planning, request transactions, non-carrier scanning, and final outbound validation. A path-aware private traversal may skip only a verified reasoning text value, not keys or siblings. Proven ordinary output uses exact complete-reference recognition but still enters DLP and lease authorization.
5. Rewrites or history enrichment can introduce new leaves, merge text, trim values, restore arguments, or change item ownership. Verify each supported source-to-target correspondence; reclassify changed or unknown values strictly. A cache hit, cache allocation owner, successful history enrichment, or `ChatHistoryProvenance::IndependentReadable` is not this feature's proof.
6. Resolve final URL and actual sent authentication after all provider/header/account overrides or refresh. Recheck against the prepared proof before **both** reqwest and raw Hyper send paths (and any equivalent transport branch). A late binding mismatch discards the prepared authority/candidate, then rebinds and reprepares from immutable input or refuses. Binding only during earlier `prepare_owned_attempt` is insufficient when later header assembly can change it.
7. Final validation checks the actual encoded body's protocol-aware leaves, keys, metadata, decoded tool arguments, residual DLP findings, and exact proof eligibility. Do not substitute a sanitized inspection projection for the outbound body. Retries/failover use fresh attempt capabilities; no authority can be inherited merely because a previous attempt matched.

### Compatibility rules

- Generic Chat does not add `reasoning_content: "tool call"` for an assistant tool call with absent reasoning. Missing/false compatibility capability stays off, including old deserialized configs.
- A narrowly named explicit compatibility capability may retain a placeholder only for upstreams that require it. The concurrently introduced `CodexChatReasoningConfig.requires_tool_reasoning_placeholder` / `requiresToolReasoningPlaceholder` is a candidate source location; confirm its actual merged callers before reuse. Do not infer enablement from provider/model names, tool presence, `supportsThinking`, or a failed provenance lookup.
- Synthesized placeholder text is not upstream reasoning and cannot receive a delivered-origin exemption. Existing real reasoning must not be overwritten or appended to a fabricated placeholder.
- Long `<thinking>...</thinking>` parsing requires exact `CodexChatReasoningConfig.output_format = Some("thinking_tags")` / `outputFormat = thinking_tags`; absent, false-equivalent, `think_tags`, differently cased, or whitespace-padded declarations do not enable it. Generic Chat preserves literal long tags as ordinary content. Existing short `<think>...</think>` behavior stays unchanged. Use bounded incremental parsing for long-tag text only on the explicit path; never strip tags globally or treat tag contents alone as incoming origin proof.

## 6. Resource, publication, and privacy rules

### Optional proof budgets

| Scope                                       | Maximum proof payload   |
| ------------------------------------------- | ----------------------- |
| One response, including pending capture     | 256 KiB (262,144 bytes) |
| One live namespace, pending plus published  | 1 MiB (1,048,576 bytes) |
| Global, all namespaces and pending captures | 8 MiB (8,388,608 bytes) |

Use an **isolated optional ledger** with the existing reserve-before-allocation ownership discipline; do not consume mandatory request/response `PayloadBudget` headroom. The inspected mandatory default is 64 MiB; the optional 8 MiB is not a replacement or an increase of that mandatory limit. An equivalent priority-reclamation design requires proof that optional retention cannot cause mandatory failure, so it is not the default implementation choice.

Reserve all applicable response/namespace/global allowances atomically or with complete rollback **before** allocating, copying, indexing, or growing proof-owned text, descriptors, IDs, vectors, shared backing/control blocks, or replacement structures. Charge actual retained capacity and overlapping old/new allocations, not just text length. Immutable sharing may charge one backing once; distinct copies need distinct reservations. Borrow already-owned bytes before sizing; do not allocate a temporary clone to discover its size.

For a concrete conservative metadata bound, include all proof-owned metadata in the same charged ceilings above, even though the approved numbers are payload maxima; also cap eligible leaves at 4,096 per response and published response records at the existing completed-context ceilings of 1,024 per namespace and 16,384 globally. These count caps do not grant uncharged allocations. A strict total cap may skip proof earlier than the payload-only ceiling, which is safe; it must not interrupt forwarding. Tests must separately assert text bytes, metadata capacity, live owners, and release accounting.

Reserve pending captures against namespace/global limits too, so concurrency cannot oversubscribe them. On any limit miss, allocator/store unavailability, unsupported capture mapping, contention failure, or publication race, discard **all** pending proof for that response and continue the mandatory path. No prefix proof, subset of leaves, sampled text, hash-only fallback, or delayed partial capability. A later request without proof takes strict fallback; optionality does not promise that every replay will succeed. Removal/reset/replacement releases allocations before their charges, including pinned readers; destruct payload owners outside store locks. Never hold database locks or run blocking persistence in forwarding.

### Diagnostics and fixtures

Do not write reasoning/output text, token references, raw tool arguments, private configuration, credentials, source text hashes/digests, identity fingerprints, or proof lookup keys to logs, diagnostics, persisted/serialized proof, or test reports. This includes debug paths, client error bodies, assertion diffs, diagnostic snapshots, counters with payload-derived labels, and new provenance audit fields. Normal validated request/response wire encoding and mandatory in-memory raw snapshots are not prohibited. Use fixed stage/reason/carrier labels and bounded nonidentifying counts only; do not expose whether a particular secret or reference matched.

The inspected forwarder already has a request-body hash diagnostic and converters have historical diagnostics. Do not copy those patterns into this feature. Suppress payload/hash-bearing diagnostics on new proof-bearing paths where necessary; broad unrelated logging cleanup is not permission to expand scope. Preserve existing security refusal codes and sanitized observations. Optional proof/audit failures must not promote a refusal to forwarding or interrupt an otherwise valid response.

Use synthetic fixtures only. Assertions involving protected data must be fixed boolean/fixed-error assertions, not `assert_eq!`/pretty-debug output that would echo text, references, tool arguments, or hashes on failure. Test ledger observations must contain only charges/phases/counts. No real transcript, credential, tool invocation, app listener, or production identity fixture.

## 10. Decisions, alternatives, and remaining implementation hazards

| Decision                                                            | Rejected alternative                                                            | Reason                                                                                        |
| ------------------------------------------------------------------- | ------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| Typed exact in-memory leaf capability                               | Trust all assistant/reasoning roles, hashes, IDs, cache hits, or a whole object | Prevents client-controlled bypass and strict-sibling laundering.                              |
| Reasoning exemption distinct from ordinary output exact recognition | Apply one permissive scanner to all history                                     | Complete references in ordinary output remain authorized; upstream reasoning text is literal. |
| Independent delivered capture                                       | Reuse tokenized completed-context snapshots or legacy converter cache           | They contain different bytes/normalizations and serve different authority.                    |
| Atomic optional publication after mandatory completion              | Publish on deltas/item.done or keep first leaves after budget miss              | Prevents partial/incomplete response capability.                                              |
| Isolated optional allocation ledger                                 | Retain proof in mandatory headroom without priority reclamation                 | Optional bookkeeping must not break forwarding.                                               |
| Exact actual binding at final send                                  | Bind configured target/auth before late header resolution                       | Prevents retry/auth/override time-of-check/time-of-use mistakes.                              |
| Default-off explicit compatibility                                  | Provider-name inference or global tag filtering                                 | Keeps generic Chat semantics and avoids fabricated reasoning authority.                       |

No unresolved product-policy decision is delegated to implementation. API/type spelling and module placement can adapt to merged code, not security semantics. The principal execution hazards are duplicated scanners, converter trimming/merging, token-empty early exits, late auth assembly, optional-memory starvation, and confusing completion snapshots with delivered text. If any cannot be covered by HP-01–HP-15, stop that implementation slice and report it to the parent before widening an exemption. Unsupported protocol shapes stay strict/unsupported rather than gaining implicit coverage.
