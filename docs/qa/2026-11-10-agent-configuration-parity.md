## Reference and scope

Reference: [yetone/magpie at b45d21d5fb39ca0590e653ca33d6f72bb65d117b](https://github.com/yetone/magpie/tree/b45d21d5fb39ca0590e653ca33d6f72bb65d117b), fetched on November 10, 2026. This review covers the 18 Agent entries implemented by VaryAI, concentrating on native configuration paths, provider schemas, default-model selection, synchronization and restoration. A matching schema or a synthetic test does not establish every upstream feature or live-client acceptance.

## Harness incident

The installed desktop profile retained the VaryAI end comment but had lost its begin comment. Its managed route, credential header, native-provider copies and default model still matched the private connection receipt. The old `sections` parser rejected the comment mismatch before either the native model read or reconnection could proceed. The origin of the comment edit was not established. The missing begin comment recurred during verification, while Magpie was also running on this machine; this is evidence of a concurrent profile rewrite, not proof of the writer. A second checked comment-only recovery retained the same route and default. Unquoted `off` keys in the rewritten YAML were interpreted using YAML 1.2 semantics when comparing with JSON receipts.

The immediate local recovery added only the missing comment, after checking the route and surrounding YAML values against the receipt, retaining a private backup and checking for concurrent edits. Parsed YAML data was identical before and after. The running application was neither installed nor replaced. A live Harness conversation was not performed.

The source fix follows `dshPutRoute` and the client-save fixtures in Magpie's `dsh_route_test.go`: parse actual Cordis entries, merge routes into the existing `llm-pi-ai` entry, and update the native default-model entry. Comments no longer determine whether the configuration is readable. Old receipt values and appended adapter copies are normalized for comparison and recovery. Unknown native providers, unrelated patch entries and native selections remain part of the native configuration.

Read-only inspection of the installed official Harness bundle's public `@deepseek-ai/dsh-llm-pi-ai/lib/index.js` confirmed the three supported protocols, header pass-through, reasoning-level schema and native compatibility/timeout fields. No installed application code was executed for that inspection.

The shared Harness catalog now uses the upstream adapter's three protocol routes, Anthropic's root base URL, Responses compatibility flag, native Claude/GLM adaptive-thinking declarations, 600,000 ms default stream-idle wait and compaction-aware output ceiling. Native protocol, timeout, additional headers and per-model compatibility edits can be retained without treating an endpoint or credential replacement as ownership. Existing local gateway authentication stays in headers; this does not migrate Harness's private account credential store.
