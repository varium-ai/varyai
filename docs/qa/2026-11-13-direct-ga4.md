# Direct desktop GA4 statistics

The desktop application now loads gtag.js directly with public Measurement ID
`G-2R2MZ76G1E`. Installation and activity statistics no longer call the Vary AI
server. No server files, deployment configuration or production credentials were
changed. No Measurement Protocol API secret is required.

The enabled-by-default Settings switch remains available in all four runtime
languages. Disabling persists the choice, clears the installation ID, cancels
pending work and destroys the analytics WebView. Re-enabling creates a new ID.
Schema 3 retains valid legacy IDs and disabled choices, but resets markers from
the old backend transport. Same-day version changes have a separate event so
that they do not create another daily-active event.

A stable two-number GA4 client ID is derived from the local random UUID; no hardware identifier is used. A callback that crosses the UTC+8 midnight boundary triggers a prompt new-day check rather than waiting another day.

Google's code runs in a separate hidden, incognito WebView. It has no plugin
capabilities, cannot navigate away from its local analytics asset, and receives
only the small native report object. An explicit native invoke guard denies all
application commands except a one-time dispatch acknowledgement tied to the
pending token. The packaged main view's CSP remains unchanged; only responses
for the isolated analytics view receive the Google-specific CSP. Window-state
persistence excludes that view. The production bundle test checks that analytics
cannot import application state or UI chunks.

The Google tag can add standard metadata and automatic events, including
connection/device information. Its callback confirms dispatch processing, not
Google ingestion. Retried events can be duplicated; use distinct client IDs for
custom installation/activity reports. An observation is not proof of an OS
installation. See [data and network behavior](../data-and-network.md).

## GA4 report setup

Use the existing web stream with Measurement ID `G-2R2MZ76G1E`. Create event-scoped
custom dimensions for `app_version`, `desktop_os`, `desktop_arch` and
`statistics_date` as needed. In Explorations, filter by
`desktop_install_observed` or `desktop_daily_active` and inspect Total users,
with `statistics_date` for the application's UTC+8 statistics day. A new local
ID or a new stream creates a new observation; clearing data or disabling and
re-enabling can therefore increase the observed count. Do not treat raw event
counts, GA4 First visit, engagement or session metrics as exact installation/DAU
counts. Website and desktop identities are independent even within one stream.
