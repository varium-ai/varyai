# Support

## Start here

VaryAI is preparing its public repository and project-owned support channels. This document describes how to prepare a useful report; it does not promise a response time or a support entitlement.

1. Read the [README](README.md) and [troubleshooting guide](docs/troubleshooting.md).
2. Check [the contribution guide](CONTRIBUTING.md) for setup and validation commands.
3. Once public, search issues in the **VaryAI repository**, including closed reports, before creating a new one.

Use the VaryAI repository's issue templates for reproducible bugs, feature requests, documentation corrections, and usage questions. During private preparation, coordinate with the project owner. No public Discussions or commercial support channel is announced here.

CC Switch is the upstream project. Its tracker and maintainers are not the support channel for VaryAI-specific changes.

## What makes a useful report

- VaryAI version or full commit SHA, operating system, and architecture.
- Relevant CLI/tool version and the smallest steps that reproduce the behavior.
- Expected and actual results, with a synthetic configuration when needed.
- Redacted logs or screenshots. Remove API keys, authorization headers, cookies, private endpoints, local usernames, prompts, and conversation content.

For potential vulnerabilities, follow [SECURITY.md](SECURITY.md) and keep the report private. For community conduct concerns, see [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md).
